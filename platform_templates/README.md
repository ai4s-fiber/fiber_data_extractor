## 当前正式绑定：材料数据链 v0.3.2

`ai4s-material-chain-template-v0.3.2.json` 是当前前端直传使用的正式
模板。它基于原始科研录入表，只保留材料业务字段，一条平台记录对应一个
实际样品，顺序固定为：

1. 文献、样品与成分；
2. 工艺；
3. 结构；
4. 性能；
5. 来源与备注。

平台原生导出器会忽略同级块的 `_ord` 并按 Java `HashMap` 顺序输出，
还会漏掉多个并列结果区。v0.3.2 因此只在对象、操作、结果三个区域各放
一个 `t=9` 有序组合字段；“结构、性能与来源”位于同一个组合字段内，
从而保证 31 个字段完整且按原表顺序导出。

| 实际样品记录 | 12 条、12 个唯一数据 ID |
| 平台原生 Excel | 31 个业务字段完整，顺序与原表一致 |

## 设计边界

- 一条平台记录对应一个 AI4S 样品实体。
- `数据记录键` 根据投影版本、论文 ID 和 `entity_key` 确定性生成；
  同一投影重复导出时保持不变。
- `投影版本` 当前应填写 `chemical_fiber_projection_v1`。
- 只有四个记录级字段必填：
  `数据记录键`、`投影版本`、`文献编号`、`数据状态`。
- 平台按整个模板校验字段名称唯一性，而不是只校验同级字段。因此明细字段
  使用稳定的业务前缀，例如 `成分单位`、`工艺参数单位`、`结构单位`、
  `性能单位` 和 `长尾单位`；这些前缀不能删除。
- 论文没有报告的科学字段保持空缺，不生成虚假的“未报告”空行。
- 数组中的一条明细一旦创建，对应业务域的核心名称、原始值和抽取状态字段
  需要填写。
- 数值型和范围型都是可选的解析结果；无论是否能可靠解析，始终保留
  对应业务域的原始值字段。
- 同一固定标量字段出现多个不同值时，适配器按“状态、来源、证据、
  置信度”的稳定优先级选择主值，其余候选保留到“其他未映射指标”，
  同时把记录标记为“待复核”；不会静默覆盖。
- 只有证据但尚无原始值的 `pending_facts` 不生成伪造空行，会计入
  “待复核数量”和质量审核意见；即使它没有对应样品实体，也会生成一条
  未分配的待复核记录，避免事实被漏掉。
- `发表年份` 只填写四位整数；所有以“置信度”结尾的字段和
  `证据覆盖率` 均使用 `0–1`，不使用百分数。

## 模板结构

| 平台区域 | 内容 | 对应 AI4S 数据 |
|---|---|---|
| 文献与样品 | 文献、样品、材料、变量及记录状态 | `paper`、`SampleCatalog` |
| 制备与处理摘要 | 工艺路线、纺丝方法、摘要和证据 | `CandidateRecord` 摘要字段 |
| 审核与附件 | 记录审核状态、PDF、补充材料、图片 | 审核字段及未来附件绑定 |
| 成分与配方明细 | 可重复的组分及含量事实 | `FactCandidate.fact_type=composition` |
| 工艺参数明细 | 可重复的工艺阶段和参数 | `FactCandidate.fact_type=process` |
| 结构测试结果 | 可重复的结构指标 | `FactCandidate.fact_type=structure` |
| 性能测试结果 | 可重复的性能指标 | `FactCandidate.fact_type=performance` |
| 其他未映射指标 | 暂无稳定模板路径的长尾事实 | `unmapped_facts` |
| 数据质量与溯源 | 映射版本、签名、覆盖率和计数 | 投影中的 `quality` |

候选字段使用以下展示值：

- 数据状态及明细抽取状态：
  `已抽取`、`已验证`、`待复核`、`抽取中`、`未报告`、`不适用`
- 记录审核状态及性能审核状态：
  `待审核`、`已修改`、`通过`、`存疑`、`缺失`、`已删除`

适配器显式映射内部英文状态，不依赖字符串猜测。

| AI4S 内部状态 | 平台展示值 |
|---|---|
| `extracted` | 已抽取 |
| `verified` | 已验证 |
| `needs_review` | 待复核 |
| `extraction_pending` | 抽取中 |
| `not_reported` | 未报告 |
| `not_applicable` | 不适用 |

## 导入前验证

从仓库根目录打开 PowerShell：

```powershell
python platform_templates\validate_platform_template.py `
  platform_templates\ai4s-chemical-fiber-template-v0.1.json
```

预期输出类似：

```text
VALID: ai4s-chemical-fiber-template-v0.1.json (111 nodes; ...)
```

验证平台批量数据 canary：

```powershell
python backend\app\services\platform_batch_adapter.py `
  --batch-template platform_templates\canary\platform-batch-canary.json `
  --projection platform_templates\canary\chemical-fiber-projection-canary.json `
  --output exports\platform-batch-canary-rebuilt.json `
  --exported-at 2026-07-27T16:45:00+08:00
```

命令会在写文件前执行严格验证，并输出数据集 ID、模板 ID、记录数、
数据 ID 唯一数和记录键唯一数。`--batch-template` 中已有的 `data`
会被忽略，只保留平台下载的 `dataset` 和 `template` 协议包络。

也可以单独检查 JSON 语法：

```powershell
Get-Content -Raw -Encoding UTF8 `
  platform_templates\ai4s-chemical-fiber-template-v0.1.json |
  ConvertFrom-Json |
  Out-Null
```

## 在平台中的操作

1. 进入“模板创建”并完成基础设置，建议模板名填写
   `AI4S 化学纤维数据模板 v0.1`。
2. 如果页面中已经导入过旧版结构，先点击“清空”，不要在旧结构上叠加导入。
3. 在“模板设计”页面点击“JSON解析”。
4. 点击“选择JSON文件”，选择
   `platform_templates\ai4s-chemical-fiber-template-v0.1.json`。
5. 确认导入后先点“预览”，不要立即覆盖已有生产模板。
6. 核对左侧大纲应包含：
   - 文献与样品
   - 制备与处理摘要
   - 审核与附件
   - 成分与配方明细
   - 工艺参数明细
   - 结构测试结果
   - 性能测试结果
   - 其他指标与质量
7. 点开字段设置，确认只有
   `数据记录键`、`投影版本`、`文献编号`、`数据状态`
   是记录级必填。
8. 核对四个明细数组均为“数组 → 容器 → 子字段”。
9. 核对“原始论文PDF”的单个字段值不允许多文件；补充材料和关键图像允许
   多文件。
10. 先点击“暂存”，再进入“数据量规则配置”。

## 数据量规则

当前私有开发模板已经按“整个模板计入”配置并完成一次真实数据回读。新建
模板时仍需要在界面中核对以下规则：

| 平台片段 | 建议数量 |
|---|---|
| 文献与样品对象 | 恰好 1 |
| 制备与处理摘要 | 0 或 1 |
| 审核与附件 | 0 或 1 |
| 成分与配方明细结果片段 | 0 或 1；内部数组 0 到多条 |
| 工艺参数明细结果片段 | 0 或 1；内部数组 0 到多条 |
| 结构测试结果片段 | 0 或 1；内部数组 0 到多条 |
| 性能测试结果片段 | 0 或 1；内部数组 0 到多条 |
| 其他指标与质量结果片段 | 0 或 1；表格内部 0 到多行 |

不要把四个明细结果片段本身设成可重复。重复事实由片段内部数组承担，
“其他未映射指标”则由同一表格中的多行承担。

## 平台批量上传流程

日常使用优先进入 AI4S 前端“数据管道”：

1. 运行导入预检，确认论文数、平台记录数、批次大小和批次指纹；
2. 点击“登录平台”，输入平台账号、密码和当次验证码；
3. 点击“直接导入平台”；
4. 页面会完成分片上传、合并和上传记录轮询。只有平台同时返回上传成功与
   解析成功，才显示最终成功；仍在解析时重复点击只查询既有批次。

账号密码不会写入 AI4S 数据库。平台 bearer token 只放在后端进程内存中，并以
随机会话句柄与当前 AI4S 项目绑定；过期或后端重启后需要重新登录。

下面的命令行流程保留给离线验证、排障和人工上传：

项目级一键导出命令：

```powershell
python backend\scripts\ops\export_platform_batch.py `
  --project-id 1 `
  --batch-template platform_templates\canary\platform-batch-canary.json `
  --expected-dataset-id 2081660157305163778 `
  --expected-template-id 2081658374180704257 `
  --batch-template-sha256 D001D4D70DF42A34644CF8704DD77EDE99DC6EB7E89626B8778CD353D34465A2 `
  --output exports\AI4S平台批量数据.json
```

该命令先从 AI4S 数据库按论文生成可审计投影，再生成并严格校验一个平台
批量文件。默认只读取状态为 `review` 或 `completed` 的论文；不会登录平台，
不会写入外部系统，也不会保存浏览器 cookie。需要保留逐论文中间投影时，
增加 `--projection-dir <目录>`。数据集 ID、模板 ID 和 SHA-256 三项绑定参数
都是必填项，命令会在任一项不匹配时直接失败；不能通过省略参数绕过。
切换目标数据集后，要用新下载文件的实际值替换它们。

随后按平台支持的流程导入：

1. 使用目标数据集下载的批量 JSON 模板作为 `--batch-template`。
2. 运行项目级导出命令生成上传文件。
3. 在平台“上传数据 → 批量上传”中选择生成的 JSON 并提交。
4. 进入“上传下载记录”，必须同时确认“上传状态=成功”和
   “解析状态=成功”。
5. 进入目标数据集，核对数据量、数据行和至少一条记录的关键字段。

不能只把“文件开始上传”提示当作成功；解析是异步步骤。

### 协议安全要求

- 平台模板 ID 和数据集 ID 都大于 JavaScript 安全整数上限
  `9007199254740991`。不得用 JavaScript `JSON.parse` /
  `JSON.stringify`、Excel 数值单元格或浮点数中转这些 ID。
- 适配器使用 Python 整数和 JSON 序列化，能够保持 19 位 ID 精确。
- 数组型字段必须是自然数组，例如 `[{"参数名称": "..."}]`。
  平台下载器目前可能生成 `{"默认字段": ["..._item..."]}` 形式的
  占位示例，该形式会被适配器拒绝。
- 候选字段只能写入模板枚举中的中文值；未知内部状态统一降级为
  `待复核`。
- 投影中的每个值必须保留非空 `raw_value` 或 `value_text`；缺值事实只能
  放入 `pending_facts`。非对象值、未声明实体、重复 `fact_id` 和不安全的
  附件相对路径都会在生成上传文件前被拒绝。
- 每个批次内的 `meta.数据ID` 和 `数据记录键` 必须唯一。平台尚未提供正式的
  幂等键；前端直传会用确定性批次 SHA-256、本地回执和平台上传记录联合防重，
  不会对已成功或仍在解析的同一批次盲目重传。
- 附件字段在 JSON 中填写相对路径；带附件时，JSON 和附件必须按平台规则
  放在 ZIP/RAR 第一层后再上传。

## 仍保留的边界

- 当前闭环使用平台网页本身调用的批量文件接口，没有把浏览器 cookie、平台密码
  或 bearer token 写入 AI4S 数据库，也没有绕过验证码和平台认证。
- 这些网页接口尚未形成对外发布的正式契约。平台升级后必须重新跑真实 canary；
  删除/回滚语义仍不明确，因此 AI4S 不提供自动删除或自动回滚。
- 当前防重是客户端侧的确定性指纹与历史记录联合校验，不等同于平台服务端提供
  原子幂等键；人工在平台另行上传同一文件仍可能产生重复数据。
- 无附件 JSON 已实测；带 PDF、补充文件和图片的压缩包仍需单独 canary。
- 切换正式数据集或修改平台模板后，必须重新下载批量模板、运行本地验证，
  并先上传一条私有 canary。
